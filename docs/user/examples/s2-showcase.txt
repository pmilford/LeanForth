LeanForth's showcase: ten proof files, fifteen theorems.

What this is. LeanForth checks proofs written in LeanForth text, with its own tactics and its own
kernel. Lean is not run at all by this command. For each theorem the page shows four parts:

  A. the proof as written in LeanForth;
  B. the same proof as a Lean user would write it, for comparison (copied from the Lean file
     that the tests compare LeanForth's result with);
  C. what LeanForth did: how it read the statement, then each tactic step with the goal before
     the step and what was left after it;
  D. the verdict of LeanForth's kernel on the finished proof.

How to read a goal. A goal is what remains to be proved. Lines of the form  name : type  say what
is given (for example  n : Nat , "n is a natural number"); the line after the mark ⊢ is what must
be shown. "case zero" names the case of an induction that the goal belongs to.
Not yet as short as Lean: in goals about lists (the theorem ps_length_append) LeanForth's printer
writes every hidden argument out, marked with @, where Lean would print  (xs ++ ys).length .

The command, and its two input files:
  SHOWCASE_LIBRARY="--snapshot init.lfsnap --elab-data init.elab.ndjson" scripts/showcase-steps.sh
- init.lfsnap is a saved snapshot of Lean's Init library (59,349 declarations), already checked by
  LeanForth's kernel. It is loaded so that a new theorem can use what Init proves.
- init.elab.ndjson is the "elaboration data": facts about Init that are not part of its proofs but
  are needed to read a new theorem as Lean would: which arguments are implicit, the type-class
  instances (such as "+ on Nat"), notation and reducibility settings. Lean exported it once.
  LeanForth uses it to build the proof term, and the kernel then checks that term, so wrong data
  cannot make a false theorem accepted.

This run: 2026-11-19, gforth-fast, commit 106e01c2 (the checker is main 76c4c93e's). Every file exited
with status 0. Time: 369 s for the ten files while other jobs shared the machine; one file alone
took 11 to 17 s in two runs the same day, nearly all of it loading the snapshot.
