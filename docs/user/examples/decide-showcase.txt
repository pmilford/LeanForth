\ LeanForth's showcase of by-decide: twenty-three theorems, written with Lean's symbols and typed in ASCII.
\
\ What this is. LeanForth checks proofs written in LeanForth text, with its own tactics and its own
\ kernel. Lean is not run at all by this command. Every theorem here is a closed fact about natural
\ numbers or truth values (no variables in what is to be proved), and its whole proof is the one
\ tactic by-decide: LeanForth works the statement out by computation, builds a proof term from the
\ result, and its kernel checks that term. A false statement is refused: for  6 7 * 43 =  LeanForth
\ prints Lean's own message, "Tactic `decide` proved that the proposition 6 * 7 = 43 is false".
\
\ The page has three parts:
\   Part 1. Nine theorems written with Lean's symbols:  * + = > ≥ ≠ % ∧ ¬ ∨ ↔ < ≤
\   Part 2. The same nine typed on a plain keyboard:    >=  Ne  /\  Not  \/  <->  <=
\   Part 3. Five theorems with powers ( ^ ), subtraction and division, checked against all of
\           Lean's Init library: a Mersenne number that is not prime, Euler's factor of the fifth
\           Fermat number, Ramanujan's 1729.
\
\ Each theorem is shown in four parts:
\   A. the proof in LeanForth: the input, the text of the proof file;
\   B. the same proof in Lean, for comparison. This is NOT LeanForth's output: the showcase script
\      copies it from the Lean file that the tests compare LeanForth's result with;
\   C. what LeanForth did: LeanForth's output (its step log), laid out by the showcase script: how
\      it read the statement, then the tactic step with the goal before it and what was left;
\   D. the verdict of LeanForth's kernel on the finished proof: LeanForth's output, as printed.
\
\ Comments. Explanations are comments on the right: after a backslash, LeanForth's comment mark,
\ or after -- , Lean's, in the Lean part. Everything else is proof text, goals or output.
\
\ How to read the LeanForth text. It is postfix, as in Forth: the operands first, then the operation.
\   6 7 * 42 =                    is  6 * 7 = 42
\   3 3 * 4 4 * + 5 5 * =         is  3 * 3 + 4 * 4 = 5 * 5
\   20 10 >  10 10 ≥  3 4 ≠  ∧ ∧  is  20 > 10 ∧ 10 ≥ 10 ∧ 3 ≠ 4
\   2 32 ^ 1 +  641 6700417 * =   is  2 ^ 32 + 1 = 641 * 6700417
\ Each symbol means exactly what it means in Lean and builds the term Lean builds: the tests compare
\ the terms node for node with Lean 4.35.0's.
\
\ How to type each symbol. Every symbol that is not on a plain keyboard has a typed spelling, Lean's
\ own where Lean has one:
\   ≤  <=       ≥  >=       ∧  /\       ∨  \/       ↔  <->
\   ≠  Ne       ¬  Not      ∣  Dvd.dvd      (Lean has no typed symbol for these: the names are Lean's)
\ and  + - * / % ^ = < >  are typed as they are. Part 2 is Part 1 typed this way; the two build the
\ same terms. Not yet: a minus sign in front of a number, and by-decide on a divisibility statement
\ ( ∣ ), which stops as "not supported yet".
\
\ How to read a goal. LeanForth prints goals in Lean's notation. A goal is what is still to be
\ proved: after the mark ⊢ ("show that"), the statement to prove.
\
\ The commands, and their input files:
\   Parts 1 and 2 (12 s for both files):
\     SHOWCASE_LIBRARY="--env tests/front/decide-slice.ndjson --elab-data tests/front/decide-slice.elab.ndjson" \
\       scripts/showcase-steps.sh tests/front/tactics/decide/dc-symbols.lf tests/front/tactics/decide/dc-ascii.lf
\   Part 3 (35 s, nearly all of it loading the snapshot):
\     SHOWCASE_LIBRARY="--snapshot init.lfsnap --elab-data init.elab.ndjson" \
\       scripts/showcase-steps.sh tests/front/tactics/decide/dc-symbols-init.lf
\ - decide-slice.ndjson is a small part of Lean's Init library (about 1,260 declarations: the
\   natural numbers, their operations and the facts by-decide needs), exported by Lean. LeanForth's
\   kernel checks every one of them again in each run, before the file's own theorems: that is the
\   line "N declarations: N accepted" at the end of each file.
\ - init.lfsnap is a saved snapshot of all of Init (59,349 declarations), already checked by
\   LeanForth's kernel; Part 3 needs it because powers use parts of Init the small slice leaves out.
\ - The .elab.ndjson files are the "elaboration data": facts about those declarations that are not
\   part of their proofs but are needed to read a new theorem as Lean would: which arguments are
\   implicit, the type-class instances (such as "* on Nat"), notation and reducibility settings.
\   LeanForth uses it to build the proof term, and the kernel then checks that term, so wrong data
\   cannot make a false theorem accepted.
\
\ This run: 2026-11-20, gforth, commit a35f8d00. Every file exited with status 0.
