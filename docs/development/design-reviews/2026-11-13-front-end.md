# Design review of the front end (FRONT_END, FE1E, FE1G, FE1I, FE2), 2026-11-13 — blocking for S1

Reviewer: independent design reviewer (Opus), not an author of these designs; read-only. First review under the
owner's design-stage decision of 2026-11-13 (plan 9.4.7). This AI review does not replace the owner's approval.

**Verdict.** The designs follow Lean closely (every spot-checked Lean claim held except M1), but S1 cannot reach its
acceptance command with the steps assigned to it: B1-B5 block it; all are design fixes. S2-S6 are not blocked beyond
the items listed per slice.

## Blocking

- **B1. The elaborator cannot see the library while a `.lf` file runs.** FE1E §1.2, FE1G §3.2/§5 and FE2 §2.1 rule 3
  assume whnf/inferType/isDefEq/instance search on library constants during elaboration. src/cli/check-lf.fs runs the
  text against the unsealed stage, then `lfc-empty` clears the term store, and only then is the stage sealed and fed;
  src/front/meta-env.fs:5-7,64 reads core/input.fs (the fed declarations); `lf-menv-stage!` is called only in tests.
  fe1g3's §4.8: "by-sorry on a goal naming library constants answers 93 during leanforth check". The file's earlier
  declarations are also invisible to later ones. ADR D13 says front/ never uses import/, yet meta-env.fs requires
  import/stage.fs. Fix (one-page design, [import]/[bypass]): decode library declarations from the stage tier into the
  term store on demand (lfc-arity already reads the tier); bind the elaboration data with `lf-menv-stage!`; add the
  text's handed-over declarations to the Meta view; prove the text's scratch never writes below the input marks
  (`lf-input-intact?`); amend D13. An S1 step.
- **B2. FE1e0 recorded as done, but it is not.** The FE1e row says the unifier's flags and stuck signal were "done in
  FE1c (reviews I1, I2)". On main defeq.fs:47-55,349-351,685-688 answers unsupported for isDefEqStuckEx's stuck case and
  level-defeq.fs:28-33 answers false where Lean throws (2026-11-12-fe1c-lnorm.md:16: I1, I2 "fixed" by documentation).
  Missing on main: `lf-meta-stuck`, `getDecLevel`, checkTypesAndAssign's instance-typed branch (fe1c-3 I1), the
  synthPending hook, whnf with delta, whnfR, whnfForall, the telescope-reducing helpers, instantiateForall; whnfCore
  answers unsupported at any definition head; meta-env.fs:22-33 does not read format 2's matcher and aux-recursor
  facts. Probe (pinned Lean, `theorem t : 0 + 0 = 0 := by rfl`): isDefEqStuck raised 28 times (instOfNatQ,
  String.instHAddCharRaw, `Add ?α`), 0 lazy-delta unfoldings. So with main's FE1c, S1 stops unsupported at the first
  numeral; where Lean throws "stuck" on a level, LeanForth answers false, which can change which instance wins. Fix:
  reopen FE1e0 as an S1 step with that list; move "FE1c lazy delta" from S1 to S2 (S2's `0+k=k =?= Nat.add 0 k = k`
  and `0+(k+1) =?= Nat.succ ?x` need it, with FE1d2's `_sunfold`).
- **B3. Two incompatible undo-trail designs for mvars.fs.** FE1G §4.2 and FE1g-1's code: LIFO marks (mvars.fs:66-70
  "only the latest open mark may be rolled back"). FE1E §3.5 (FE1e4): snapshot switching (undo to the common ancestor,
  then redo; `lf-mctx-snapshot`/`switch`), needed by tabled resolution (Lean's withMCtx on generator and consumer
  nodes). fe1g3's `lf-tac-try` and defeq's checkpointDefEq rely on LIFO. Fix: one design in FE1E §3.5 with LIFO as the
  special case, agreed before fe1g3 merges.
- **B4. No design says where binder kinds come from.** Readers: elabAppArgs (FE1E §2.2), introN (FE1G §5.1),
  mkForallFVars/mkLambdaFVars (FE2 §3.2). The store shares nodes differing only in binder kind
  (present/binder-table.fs:1-10; fe1c-3 M1, R1 open); Lean's export can share such terms (fe6a M1). A wrong kind means
  wrong implicit arguments, a different statement (D4). Fix: FE1E §2.2 reads a constant's kinds from its own declared
  type and a local's or mvar's from its view entry, never from an instantiated node; before S1 a reference count of
  exported vs Lean binder info over Init's declaration types (target 0).
- **B5. Error-code ranges collide.** errors.fs on main reserves 74-79 for FE1c/FE1e/FE1f (74-77 used): FE1e has 2 left
  and needs about 18 (FE1E §5.3 plus §2.7 rows). On fe1g3 80-99 are all used; FE1g-5/6 need about 9 more (FE1G §4.6).
  FE1I §4.3 and FE2 §5.5 say "next free", so numbers depend on merge order. Fix: allocate now, e.g. 100-149 elaboration
  (FE1e, FE2), 150-169 tactics, 170-189 decide/omega.

## Not blocking

- **M1.** FE1E §2.6/§5.2 give by-exact Term.elabTermEnsuringType (tries a coercion → unsupported); Lean's evalExact uses
  Tactic.elabTermEnsuringType (Elab/Tactic/ElabTerm.lean:51-62, "we don't want coercions", then a type-mismatch error).
  FE1G §5.2 and fe1g3's code 96 are right; add the tactic variant to FE1E.
- **M2.** When elaboration happens is stated three ways (ADR D8/FRONT_END §4.2: when the binder word runs; FE1G §3.2:
  tactics run when read; the code — handover.fs:28, fe1g3 §4.8, tactic-syntax.fs — reads the whole declaration and
  elaborates and runs it at `end NAME`, hypotheses take no values (error 87); FE2 §2.1: a scratch elaboration while
  reading, needing B1). Write one rule: the one built.
- **M3.** Nobody owns the declaration glue: header elabType, synthesizeSyntheticMVarsNoPostponing (where S1's default
  instances fire), instantiateMVars, levelMVarToParam, the theorem statement-alone rule; it feeds FE1f's
  `lf-front-elaborate` (handover.fs:120) and fe1g3's `lf-front-by-statement`. Name it an S1 step.
- **M4.** `--fuel` is the kernel's per-declaration fuel (COMMAND_LINE.md:324); FE1E §5.3, FE1G §4.5, FE1I §6.3 and
  FRONT_END §8.4 reuse it for front-end fuel.
- **M5.** Two unsupported rules wide enough to sink S1: FE1E §2.7 answers unsupported when a candidate list merely holds
  a left-out instance (Init has 31 left out, ELABORATION_DATA.md:134); FE1E §4: one unverified class among 2,938
  instances makes every instance problem unsupported. Fix: unsupported only when the search tries that candidate;
  measure both counts for the OfNat, HAdd, Add roots first.
- **M6 (trust).** The elaboration-data file is not bound to the export (D10's manifest SHA-256 not done); priorities and
  ranks are taken on trust (FE1E §3.1), so an edited data file can change which instance a statement uses. Add the
  manifest entry before S1's [parser] gate.
- **M7.** Lean's labelled `sorryAx` (FE2 §3.8) needs string literals the export writer does not write (S5); ADR
  Amendment 1 says the word `sorry`, fe1g3 uses `by-sorry`: settle at the [parser] gate.
- **M8.** S3 needs FE1c whnf with delta, reduceNat? with the power threshold, literal-to-constructor, FE1d2's `_sunfold`
  (FE1I §4.2/§4.4); S4 needs S3 (mkDecideProof) and auxiliary declarations in FE1f's hand-over ([bypass]).
- **Low.** L1 designs put tactics in src/tactic/, code in src/front/; L2 stale status lines (FRONT_END §1, §8.2; FE1E
  "nothing written"; FE1I "nothing built"); L3 tests/frontend/01-zero-add.lf vs tests/front/01-zero-add.lf, FE1I and
  FE2 both use `02-`; L4 FE1G §5.3's rfl shortcut is required (Lean's `exact Iff.rfl` reaches a coercion search); L5
  FE2 A35 expects `?m.1` (Lean's mvar numbers cannot be reproduced).
- Spot checks that held: the rfl macro order (Tactics.lean:476-482, Core.lean:1042), MVarId.refl (Refl.lean);
  elabNumLit and mkInstMVar (BuiltinTerm.lean:203-229, TermElabM.lean:1954); elabBinRelCore (Extra.lean:497-560),
  getInstances (SynthInstance.lean:201-241); blockImplicitLambda (TermElabM.lean:1744); Decidable a structure in 4.35
