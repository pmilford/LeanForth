**L4 (low, planned as 9.4.8l AB). The claim "harmless" holds.**
- What happens: `wc-smatch` answers `wc-sm-none` at once (a partial or non-matcher application under the marker). `wc-unfold-run` then returns `m false ok` and leaves the smart frame on `wc-frames`.
- This breaks the documented contract, whnf.fs:37-38: "or e and false".
- It is not a difference from Lean:
  - Lean's `smartUnfoldingReduce?` fails, so `unfoldDefinition?` gives none.
  - The only `src/` caller is defeq-delta.fs:73-74 (`dd-unfold`). Every use drops e' on false: `dd-t-or`, `dd-s-or`, `dd-heads-new`, `dd-heads`. `dd-noted` calls the trace hook only on true.
- The stale frame and `wc-act` are reset by the next `wc-enter` (`wc-start` clears the frames), and `wc-leave` restores the mode and flags.
- Only crafted data reaches it: Lean wraps only full matcher applications in `sunfoldMatch`.
- Suggested fix (not run): resume the frames when the step ends unchanged.
  ```forth
  : wc-unfold-run ( e -- e' outcome )
    wc-delta dup ok? if drop wc-next then ok-then2? 0= if no-result exit then
    if wc-loop else outcome-ok then ;
  ```
  - Test: `1 alts+` (or a non-matcher head) then `lf-meta-unfold` gives `e false ok`.
