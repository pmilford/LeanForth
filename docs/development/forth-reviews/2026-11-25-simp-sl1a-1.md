Style findings, all low:

S1. `src/front/simp/types.fs:51-78`: `lf-simp-congr ( e fe fh ae ah -- e' h )` takes five items, stored in the record stc that the st-* words read. That is a record used as a register file. The caller already holds the function's result as a pair in `sa-r`, so pass pairs by address:
```forth
: lf-simp-congr ( e fr ar -- e' h )   \ fr ar: addresses of ( e h ) pairs
```
with st-fun, st-arg and st-both reading `fr 2@` and `ar 2@`.

S2. `src/front/simp/theorems.fs:97-99`: `sth-pair? ( l r n j -- l r n flag )` takes four items and uses `2r@` twice. Factor:
```forth
: sth-arg ( e j -- a ) over lf-meta-args# lf-meta-nth-arg ;
: sth-pair? ( l r j -- l r flag ) >r 2dup r@ sth-arg swap r> sth-arg swap sth-inner? ;
```

S3. `src/front/simp/main.fs:169-182`: `sa sa-i @` appears 6 times and `sa sa-n @` and `sa sa-e @` repeat. Name them:
```forth
: sm-i ( -- i ) sa sa-i @ ;
: sm-n ( -- n ) sa sa-n @ ;
```
and use the existing `sm-act-e` in `sm-prefix` and `sm-info`.

S4. `rewrite.fs:63` (`sr-extras`, with `>r >r … r> r>`) and `theorems.fs:71` (`sth-same?`) read two adjacent fields with `2@`. That ties the code to the field layout; it is commented, but reordering the fields would break it silently. Use
```forth
: srt-e+n ( -- e n ) srt srt-e @ srt srt-n @ ;
```

S5. `src/front/tactics/simp-only.fs:51-54`: `tso-shaped?` is a four-test `over … or` chain on constant names. Use a small name table and an any-of word.
