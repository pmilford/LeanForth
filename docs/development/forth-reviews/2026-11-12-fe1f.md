### M1 (medium; [bypass] boundary): a theorem or definition with no value is recorded, and the writer reads outside its table
`src/front/handover.fs:49-50`: `lfh-value` treats any negative value as "no value", whatever the kind. Pinned by
`tests/front/handover.fs:176` (`T{ d0 ty -1 lf-handover va -> outcome-ok -1 }T`; d0 is the theorem add_zero', though

`{"thm":{...,"value":241}}` with outcome ok; value -2 → the all-nodes writer wrote `"value":0`, an existing expression,
outcome ok. Through `cli-check` the stage refused both (exit 4) in two runs, only because of what the heap held. For a
`def`, an aliased value would be a different definition, checked as written. Malformed input from the untrusted
elaborator must fail closed. Fix in the hand-over:
```forth
\ A theorem's or definition's value is a node; an axiom has none (-1).
: lfh-axiom? ( decl -- flag ) lf-fdecl-kind @ lf-decl-def > ;
: lfh-shaped? ( decl value -- flag ) swap lfh-axiom? if -1 = else 0< 0= then ;
: lfh-checked ( decl type value -- outcome )
  rot 2dup swap lfh-shaped? if -rot lfh-go else drop 2drop outcome-invalid then ;
```
(call `lfh-checked` from `lf-handover` in place of `lfh-go`), and in the writer:
```forth
: lfx-node? ( term -- flag ) 0 lf-term-count @ within ;
: lfx-expr-ref ( term -- n )
  dup lfx-node? if lfx-expr# else drop -1 then dup 0< if outcome-unsupported lfx-refuse then ;
```
Tests: line 176 becomes an axiom; a theorem with value -1 and -2 (invalid, nothing kept); an axiom with a value
