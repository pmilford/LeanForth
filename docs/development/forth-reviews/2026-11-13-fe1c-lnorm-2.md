## 2. Findings
### M1 (medium): `lf-instantiate-mvars` gives terms pinned Lean 4.35.0 does not give
| Case | Pinned Lean | Port |
| --- | --- | --- |
| P1: delayed with k = 0, `?d y`, `?p := x` | `x y` | `?d y` |
| P16: k = 0, `?d y x`, `?p := fun b => b` | `y x` | `?d y x` |
| P12: k = 1, `?d y Prop`, `?p := fun b => b` | `Prop` | `(fun b => b) Prop` |
| P4: `?f ?d`, `?f := fun a => a y`, `?d` ready | `y` | `?d y` |
| P9: `?f y`, `?f := ?d`, `?d` ready | `y` | `?d y` |
| P13: `?f ?e y`, `?f := fun a => a`, `?e` ready | `y` | `?e y` |

After the beta step of an assigned head, Lean instantiates the result again (a ready delayed metavariable landing at a
head gets its value: P4, P9, P13); the Terms comment (mvars.fs:390) "the result not instantiated again" is wrong for
4.35.0. After a delayed substitution Lean does not instantiate again (P11 agrees). In the delayed step Lean also
beta-reduces the value against the surplus arguments (P12), and with k = 0 applies the value to the arguments (P1,
P16); the port acts only at the prefix with exactly k arguments, so k = 0 never fires (and `lf-mvar-delay` accepts
n = 0). Fix: (a) treat a ready delayed head as an assigned head whose value is `fun xs => val` (k lambdas),
beta-reduced against all n ≥ max(k, 1) arguments with no second pass (fits P1, P7, P11, P12, P16), confirmed with
pinned-Lean cases; (b) until a second instantiation pass is ported, answer unsupported when, at a beta step, f's spine
head or any argument image's spine head is a delayed metavariable whose pending value is assigned; (c) add P1, P4, P9,
P12, P13, P16 to MINST as equal cases or listed gaps; (d) correct the header, the Terms comment, FRONT_END.md and the
plan row. Probes: scratchpad/probe/minst_probe.py and minst_probe2.py.

### M2 (medium): crash when the argument slab cannot grow in the delayed step
`mv-arg-put` (mvars.fs:436-437) refuses the walk but `mv-spine` carries on; `mv-put-args` (472-473) then calls `mv-nth`
with j > `mv-args#` (a negative index into the unchecked `slab-at`), and `mv-apply` (442) runs `mv-args# swap ?do`
with s > limit, reading further below the block. Probe scratchpad/probe/delay-refused.fs (?d delayed over 40 free
variables, `?d x .. x` with 40 arguments, the k-th allocation refused): k = 1..7 answer full; k = 8 (the argument
slab's growth) dies with "Invalid memory address" (Gforth 1.0 exit 139, 0.7.3 exit 1). Fix:
```forth
\ An argument the slab refused already ended the walk: no image.
: mv-delayed ( value addr k -- image )
  dup mv-args# <> if 2drop drop -1 exit then
  dup >r lf-meta-abstract mv-remapped r@ mv-put-args r> mv-apply ;
```
plus a meta-heap.fs case like the probe (run first in its context) and a planted fault.

### L1 (low): a reused mark number, or a mark kept from before a reset, is accepted
`mv-latest?` compares depth only: open outer (1), inner (2), commit inner, open inner2 (2), assign `?a`: the stale 2
rolls back inner2's assignment; a mark from before `lf-mctx-reset` commits the new mark 1. Fix: a serial per mark (a
counter `lf-mctx-reset` does not reset), or narrow the header's claim.

### L2 (low): pending values instantiated eagerly; the occurs check ignores delayed assignments
`mv-inst-pending` (415-417) instantiates a delayed metavariable's pending value even when `?d` is bare or has too few
arguments (Lean only for an application with ≥ k arguments): P2 and P2b answer unsupported where Lean gives a term.
`lf-mvar-assign`'s occurs check follows plain assignments only; Lean's occursCheck considers delayed ones
(OccursCheck.lean:15-33): the port accepts `?p := x ?d` while `?d` is delayed to `?p`, and every later instantiation
mentioning `?d` answers invalid (cycle) where Lean gives `?d y` (P3, P3b). Fix both; add P2, P3 and tests.

### L3 (low): the beta step runs at every prefix
Every application node gets an image, so `?f a1 .. an` with m lambdas runs head-beta at each prefix: n = 25: 48 ms,
925 new terms; 50: 320 ms, 3,725; 100: 3,025 ms, 14,950 (quadratic store growth, roughly cubic time). `mv-solid`
allocates and clears a memo the size of the whole store per ready delayed application. Record as a plan task.
