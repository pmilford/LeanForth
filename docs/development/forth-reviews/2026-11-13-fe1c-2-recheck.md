## New finding
### N1 (medium, blocking): `ib-bvar` gives a wrong term for a loose index beyond the arguments
`src/front/beta-inst.fs`, `ib-bvar`, the "a larger one m less" branch:
```forth
dup ib-m < if nip ib-x exit then
nip lf-term-first@ ib-m - lf-term-bvar ib-made ;
```
At that point the stack is `( node k )`; `nip` keeps k, so `lf-term-first@` reads term number k instead of the bound
variable's index (Lean's `visitBVar` gives `Expr.bvar (vidx - n)`). Probe: `#1` with 1 argument gives `#0` (correct
only because term 1's first field happens to be 1); `#2` with 1 argument gives `#0` (want `#1`); `#3` with 1 argument
fails with outcome 6 (want `#2`); `#5` with 2 arguments fails (want `#3`); `fun _ => #3` with 1 argument gives body
`#0` (want `#2`). The unit test `1 bv fk x1 0 bv rb=` (tests/front/infer.fs) and the fault `fe-binst-no-shift` pass
only by that coincidence; a fault applying the correct code also passes all of infer.fs, whnf.fs and meta.fs. Not
reachable from `lf-infer` today, but `lf-meta-instantiate-rev-beta` is public and later telescope callers will reach
it. Fix:
```forth
: ib-bvar ( node depth -- image )
  over lf-term-first@ swap - dup 0< if drop exit then
  dup ib-m < if nip ib-x exit then
  drop lf-term-first@ ib-m - lf-term-bvar ib-made ;
```
Tests: `T{ 2 bv fk x1 1 bv rb= 5 bv fk fa x2 3 bv rb= -> true outcome-ok true outcome-ok }T`; `T{ nat 3 bv lam fk x1
nat 2 bv lam rb= -> true outcome-ok }T`; instantiateBetaRevRange cases with indices beyond the range in
check_meta.py's pinned-Lean comparison.
