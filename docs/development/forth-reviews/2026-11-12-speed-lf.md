## Findings

### L1, low: with-scratch.sh leaves its folder when killed by SIGTERM

The Makefile wraps it in `timeout` (`$(RUN) $(SCRATCH) …`), so a timed-out test is killed this way. Bash does not run the EXIT trap on a SIGTERM it does not trap.

Reproduced:
- `TMPDIR=… timeout 1 scripts/with-scratch.sh sh -c 'sleep 5'` exits 124 and leaves `lf-test-scratch.XXXXXX`.
- With SIGINT, and on normal exits, the folder is removed.

Effect: the folder is unique, so nothing collides, but the claim "folder always removed" is not true. Fix:

```bash
trap 'rm -rf -- "$dir"' EXIT
trap 'exit 143' TERM; trap 'exit 130' INT; trap 'exit 129' HUP
```

Add a test that runs `timeout -s TERM 1` and then checks the folder is gone.

### L2, low: `taken_problems` has no harness self-test

It guards the new snapshot-based mutant checks for both clamp and SHA. A fault that made it return `[]` would pass silently. Add a case to `clamp_mutants.py --test` (in `make test`, no Lean needed): fabricated reports must each be flagged when a copy has `provenance: "snapshot"`, when an original lacks it, or when the import counts are off.

### L3, low: `build/program-clamp` lasts between runs and is shared within a worktree

`program-clamp-record` overwrites the export, the evidence and the snapshot. But if `--save-snapshot` failed while the check exited 0 (`cli-snapshot-save` drops its outcome), the previous make's snapshot would be used.

That is benign today: an import must take exactly the export's declarations with `otherContent: 0`, and a stale verdict version is refused. Still:
- remove the two kept files before recording, and require the snapshot to exist afterwards;
- two makes at once in one worktree would share the folder;
- `scripts/mutants.py` copies `build/` into every mutant tree (`SKIPPED` lacks it), which costs only size and time.

### Notes (no action needed)

- **I1.** The note is chosen by the asked `--jobs`, not by the workers made. It is true today and the resources assertion pins it. `ck-parallel? ck-jobs-run? 0= and` would make it true by construction, but it would drop the note on one-core hosts, where `ck-jobs!` clamps to 1. Keep it as is.
- **I2.** In `make check`, the clamp copies are now checked only through the snapshot-import path; the plain path no longer checks them. Both paths use the same `check-declaration`, and the import accounting is asserted.
- **I3.** "First line" holds only without `--no-manifest` and `--elab-data`, as traced above. The test and COMMAND_LINE.md ("before the verdicts") are right.
- **I4.** `getenv` is a Gforth word, kept in test-only support; it runs on both pinned Gforths.
