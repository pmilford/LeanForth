## Blocking findings

**B1. Fidelity: the BitVec guard lets LeanForth accept a different term.**
- **Where:** `src/front/simp/simprocs.fs:27` (the header's claim), `:94-97` (`sp-lits?`, `sp-lit-guard`), and `:106` (`sp-family`).
- **Cause:** the guard assumes every literal-family simproc fires only when every explicit operand is a literal. Four BitVec simprocs break that:
  - `BitVec.reduceShiftLeftShiftLeft` and `BitVec.reduceShiftRightShiftRight` (`BuiltinSimprocs/BitVec.lean:447-465`) rewrite `(x <<< i) <<< j` to `x <<< (i+j)` for any `x`.
  - `BitVec.reduceHShiftLeft'` and `reduceHShiftRight'` (`:94-98`, `:221-230`) fire for any `v`. Today the lemmas `shiftLeft_eq'` and `ushiftRight_eq'` are tried first, which hides them.
  - For these, the guard answers "continue" where Lean rewrites.
- **Repro** (full Init, its 4.1 data written by me with `ELAB_FORMAT=4.1 scripts/export-elab.sh` to `$S/init/init.elab.ndjson`, checked against `.claude/work/parallel-init/init-1.lfsn`):
  - Lean: `theorem pb_shr_shr (x : BitVec 8) : (x >>> 2) >>> 3 = x >>> 5 ∨ True := by simp`
  - LeanForth: `8 BitVec explicit: x  x 2 HShiftRight.hShiftRight 3 HShiftRight.hShiftRight x 5 HShiftRight.hShiftRight = True ∨` with `by-simp`
  - LeanForth's result: **accepted** (exit 0). Its term uses `or_true`. Lean's term uses `BitVec.shiftRight_add`, `eq_self` and `or_self`. Types are equal; values differ.
  - The same goal without `∨ True` (`pb_shr_shr_eq`), and the `at[ h ]` form (`pb_shr_at`), give exit 4 with Lean's error 500 "`simp` made no progress", but Lean accepts both.
- **Fix:** register the four simprocs by name, matching the data's phase and kind:
  ```
  ' sp-crude-port 0 6 false false lf-simproc: HShiftLeft.hShiftLeft BitVec.reduceShiftLeftShiftLeft
  ' sp-crude-port 0 6 false false lf-simproc: HShiftRight.hShiftRight BitVec.reduceShiftRightShiftRight
  ' sp-crude-port 0 6 false true  lf-simproc: HShiftLeft.hShiftLeft BitVec.reduceHShiftLeft'
  ' sp-crude-port 0 6 false true  lf-simproc: HShiftRight.hShiftRight BitVec.reduceHShiftRight'
  ```
  Then add:
  - an audit test: every Init simproc whose family guard is `sp-lit-guard` must be on a reviewed list ("fromExpr? on every explicit operand", citing the Lean lines);
  - `pb_shr_shr` as an end-to-end wrong twin;
  - corrected wording in the docs (see L5).
- I checked the other families' bodies by hand (Int, Fin, Char, String, Nat; `return .visit` and `mkAppM` across all BuiltinSimprocs files). These four are the only literal-family misses I found. UInt and SInt I only skimmed.

**B2. Data trust: a duplicate rank is not refused, and drops a lemma silently.**
- **Where:** `src/front/data-index.fs:118` (`rix-place` overwrites through `slab-cell-put`) and `:124` (`rix-gapless` compares only counts).
- **Cause:** a duplicate rank plus the gap it leaves pass the count check. The gap cell then reads as left-out value -1, which is also the encoding of left-out record 0, so they cannot be told apart. The simp kinds never call the reader's `ed-place`; the instance kinds do.
- **Repro (mutation m1):** in `tests/front/simp-slice.elab.ndjson`, change `and_true`'s rank from 4 to 0 and recompute the records digest in the header and the manifest. `True ∧ True` with `by-simp` is then accepted using `and_true`. With the real data, and in Lean, the term uses `and_self`.
- **False claims:** `data-index.fs:38`, `simp-set-data.fs:31` and `ELABORATION_DATA.md:914` all say two values of one rank answer invalid.
- **Fix:** give empty cells a sentinel distinct from every value and refuse an occupied cell:
  ```
  : rix-free? ( r rix -- flag ) rix-ranked 2dup slab-count < if slab-at @ rix-none = else 2drop true then ;
  ```
  Call it in `rix-place` (outcome invalid when false). This needs a `slab-cell-put` variant that takes the fill value. Add a simp-data fixture with a duplicate rank and a planted fault.

**B3. Re-entrancy rule 4a: the simproc table's writer is not sealed.**
- **Where:** `name-table: sp-ports` (`simprocs.fs:60`) is written by `lf-simproc:` (`:63`), which never checks `context-sealed?`. The tactic registry's row writer does (`tactic-run.fs:305`).
- **Fix:**
  ```
  : sp-open ( -- ) context-sealed? abort" simprocs: a port after context-new" ;
  ```
  Call it first in `lf-simproc:`.
- Once sealed, `sp-ports` is the same kind of load-time-only registration table as the `lf-tactic:` rows. The fix round then needs baseline entries for globals: `simprocs.fs` 1 and `tactics/simp.fs` 2. `check-forth-quality.py` fails today with "globals 1 > 0" and "globals 2 > 0".

**B4. Reuse: `sp-first-part` re-implements an existing word.**
- `sp-first-part` (`simprocs.fs:104`, `2dup [char] . byte-scan nip -`) does the same job as `lf-stmt-part` (`core/statement-match.fs:292`).
- Two more copies of the phrase use other delimiters: `cli-quote-at` (`cli/leanforth.fs:854`) and `lf-stmt-span` (`statement-match.fs:88`).
- `check-duplicates.py` misses these because they are under its 6-token threshold.
- **Fix:** add to `lib/bytes.fs`:
  ```
  : bytes-before ( c-addr u char -- n ) >r tuck r> byte-scan nip - ;
  ```
  Replace all four copies with it. The core copies are behaviour-preserving refactors, ordinary work under the 2026-11-19 rule.

## Medium findings

**M2. The harness never fails on "statement elaborated differently".**
- `tests/front/check_simp_init.py` counts these cases apart and never fails on them.
- I ran the harness steps once in scratch (Lean side, then `check_simp_init.py` against the snapshot) and reproduced K = 57 with 0 different terms.
- The two cases are `Int.Nonneg.natCast` (si_0564) and `Vector.range'_one` (si_0622). I elaborated the printed texts in pinned Lean: type and value equal LeanForth's node for node. So they are the printer losing a numeral's type or the `#v[..]` notation, not elaborator bugs.
- **Fix:** have the harness's Lean side elaborate the printed text and count a real difference as a BUG.

**M3. Portability: the dsimp scan can exceed the guaranteed data-stack depth.**
- `sm-kept?` (`main.fs:216-241`) keeps up to `sm-scan-most` = 64 nodes on the data stack while deep words run (rfl matches, menv lookups, keys).
- Forth-2012 guarantees only 32 data-stack cells.
- **Fix:** use a context slab for the work list (`slab-push` / `slab-pop`). That also gives `sm-scan-step` a fixed stack effect.
