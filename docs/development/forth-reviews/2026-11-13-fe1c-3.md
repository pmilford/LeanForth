## Findings

### B1 (blocking): Nat offsets compare unsigned values with signed `>`

src/front/defeq.fs:531-538 (`de-off-both`, `de-off-value`, `de-value-off`). nat-offset.fs accepts values up to
2^64-1 (`lf-lit-small?` allows one full limb; `no-add-acc` and `no-off+` check unsigned overflow); the three words
compare them with signed `>`. Reproduced against pinned Lean 4.35.0 (…/scratchpad/rv-probes/probe.py):

| Case | Lean | LeanForth |
| --- | --- | --- |
| `Nat.succ ?h =?= 9223372036854775808` (2^63) | true, `?h := OfNat.ofNat Nat 9223372036854775807 …` | false |
| `9223372036854775808 =?= Nat.succ ?h` | true | false |
| `Nat.succ (?h + 2^63) =?= 5` | false | **true**, `?h := OfNat.ofNat Nat (2^63+4) …` |
| control `Nat.succ ?h =?= 2^63-1` | true | true |

Fix: `u>` in all three words. Tests: boundaries at `max-n 1+` (2^63), 2^64-1 and a sum crossing 2^63 (three 2^62
addends) in tests/front/defeq.fs and check_defeq.py; defeq-cases.fs:25 prints literals with signed `0 .r` (use
`0 u.r`); check_defeq.py:245 writes decimal literals Gforth wraps silently at 2^64 (assert n < 2**64); state in
nat-offset.fs's header (line 18) that values are unsigned cells. The reviewer's fault `rv-off-unsigned` survived every
test.

### M1: FunInfo reads binder kinds from a shared node

src/front/fun-info.fs:102 (`fi-kind`, via `lf-pres-binder@`). Binders differing only in kind are one node and the
binder table holds one kind per node: store nodes, last writer wins (`lf-pres-binder!` overwrites); input nodes, the
input record's kind; copy failures are dropped (`lf-pres-binder! drop` in src/front/instantiate.fs:166, mvars.fs:426,
level-params.fs:122, meta-spine.fs:54), so a full heap silently turns a kind explicit. Probe: `Eq.refl.{1}` and
`rfl.{1}` infer to the same type node; their kinds came out right because each instantiation rewrites the shared kind
just before the telescope reads it. Exposed: fvar and mvar heads (isDefEqMVarSelf -> isDefEqArgs). A wrong kind
changes isDefEqArgs's order and which pairs get the implicit-transparency bump; at default transparency only the order
changes (which can change Lean-style answers through assignments and first-order approximation); at reducible or
instances transparency it can change answers directly. No end-to-end divergence built. Fix: take kinds from the binder
occurrence (constants: the declaration's own input type; locals and metavariables: their declaration), or answer
unsupported when the kind was not written by this call; make the copy words report full; update
src/present/binder-table.fs:1-5 ("no entry can change a verdict" is now false for the front end).

### M2: each call leaves local-context entries behind

`de-bind-one` (defeq.fs:292) and `fi-open` (fun-info.fs:104) call `lf-lctx-local`; marks do not restore the local
context. Probe: 15 -> 16 after one `u k =?= u x`, 115 after 100 calls. Lean scopes these (`withLCtx'`,

ends in full. Fix: record the count at entry and truncate at `de-bind-done`, the end of `lf-meta-fun-info` and in
`de-unwind`; an lctx check in the tests' `clean?`.
